# 환전·은퇴자금·리밸런싱 계산 노트

최초 계산 검토일: 2026-11-11, 환전 조회·UI 보완일: 2026-11-12 (한국시간). 세 도구는 사용자 입력을 계산한다. 환전은 Frankfurter 참고환율 직접 조회와 은행 매매기준율 직접 입력을 지원한다. 초 단위 시장 시세, 금융상품 금리, 추천 자산 비중은 제공하지 않는다. 수수료·투자 조건의 기본값은 임의 예시다.

## 소스와 공통 동작

- 순수 계산: `scripts/personal-finance-math.js`
- 입력·결과: `scripts/personal-finance-calculators.js`
- 페이지: `src/pages/{currency-exchange,retirement-fund,portfolio-rebalancing}-calculator.html.erb`
- 공통 금액 입력, 결과의 초점 이동·이전 결과 숨김, PNG/PDF/공유 유틸리티를 재사용한다. 금융회사별 끝수 처리와 실제 주문은 지원하지 않는다.
- 금액은 원 단위 정수, 합계 입력은 최대 1조원이다. 환전 외화와 환율은 소수를 허용한다. 계산 중 비유한 값·과도한 결과는 오류로 처리한다.

## 환전수수료

[KB증권 환전 설명서](https://fdata.kbsec.com/agree/notice55.pdf)의 매수 시 기준환율에 스프레드를 더하고 매도 시 빼는 구조를 참고했다. 문서의 특정 상품 수수료율을 현재 공시값으로 가져오지 않았다. [은행연합회 외환길잡이](https://exchange.kfb.or.kr/)는 사용자의 조건 확인용 링크다.

- 우대 후 스프레드율 = 기본 수수료율 × (1 − 우대율).
- 적용 환율 = 매매기준율 × (1 ± 우대 후 스프레드율). 매수는 +, 매도는 −.
- 외화 기준: 외화 금액 × 적용 환율 ÷ 고시 단위에 별도 비용을 매수 시 더하고 매도 시 뺀다.
- 원화 기준: 매수는 별도 비용 차감 후 받을 외화를, 매도는 비용을 차감하고 목표 원화를 받는 데 필요한 외화를 역산한다. 두 조건은 항상 같은 요청 금액으로 비교한다.
- JPY는 100엔 고시를 사용한다. 통화·직접 고시 단위 변경 시 기존 기준율을 지워 잘못된 단위 사용을 방지한다.
- 검증 예: 1,000 USD, 기준율 1,400원, 스프레드 1.75%, 우대 90%, 별도 비용 0 → 매수 1,402,450원. 우대 50% 조건보다 9,800원 적다. 100엔당 950원으로 10만엔의 수수료 전 환산액은 95만원이다.
- 송금 중계·수취 비용, 카드 국제브랜드 수수료, 현찰 권종 및 거래단위는 자동 반영하지 않는다.

### Frankfurter 참고환율 직접 조회 — 2026-11-12

지원 통화를 기존 USD·JPY·CNY·EUR에서 총 17개로 확대했다. 추가 통화는 HKD·AUD·GBP,
VND·THB·TWD·PHP·SGD·MYR·IDR·MOP·CAD·NZD다. 요청한 홍콩·호주·영국과 아시아 여행
통화를 우선 포함하고 캐나다·뉴질랜드를 보완했다. 통화 목록은 방문객 수의 순위표가 아니다.
선정 참고로 [한국관광공사 2026년 9월 주요 목적지 통계 공표](https://touraz.kr/statistics?bbsSeq=311491_1127&boardMode=V)의 범위·한계와
[2024년 주요 방문지에 대한 정부 자료의 인용](https://tour.gunsan.go.kr/_cms/board/eFileDownload/161/1819854/195c2c19523c683f1e5a38f9675a66dd)을 확인했다.
각국 자료의 기준과 포함 범위가 달라 완전한 최신 전체 순위를 만들거나 방문자 수를 추정하지 않았다.
추가 13종 모두 Frankfurter 통화별 KRW 응답의 HTTP 200·CORS 허용·유효한 기준일을 확인했다.

`exchangeQuoteUnits` 한 곳에서 지원 통화와 표시 단위를 관리한다. JPY·VND·IDR는 입력 편의를
위해 100단위로 표시하고 API의 1단위 환율에 100을 곱한다. 이 규칙을 모든 은행의 공통 고시
규격으로 주장하지 않는다. 나머지는 1단위다. 직접 입력 시 은행 환율의 단위를 맞추도록 안내하고,
외화 금액은 실제 환전 수량(예: 100만동은 1,000,000)을 받는다. 폼 선택지·입력 단위·API
정규화가 서로 일치하는지 17개 통화 DOM 검사와 추가 13종 금액 보존 검사로 확인한다.

[Frankfurter 공식 문서](https://frankfurter.dev/)와 실제 `https://api.frankfurter.dev/v2/rate/USD/KRW` 응답을 확인했다. 모든 지원 통화는 각각 자기 통화를 base, KRW를 quote로 직접 조회한다. 원화 역수나 서로 기준일이 다른 통화쌍의 교차 환산은 사용하지 않는다. 처음 네 통화와 추가 13종 모두 HTTP 200과 `Access-Control-Allow-Origin: *`를 확인했다.

- 제공값은 여러 공식 원천을 조합한 참고환율이다. 특정 은행의 고시 매매기준율이나 실시간 거래 시세가 아니다. 원천별로 하루 1회~수회 갱신된다. 기본 조합 환율의 상업적 이용은 허용되며 API 키는 필요 없다. 원천을 특정하는 별도 API는 사용하지 않는다.
- `scripts/exchange-rate-loader.js`가 브라우저에서 직접 호출한다. 인증 정보·입력 금액·수수료를 전송하지 않고 통화 코드만 URL에 넣는다. 페이지 진입·통화 변경과 명시적 불러오기 버튼에서 요청하며 자동 폴링은 하지 않는다. 10초 타임아웃·수동 입력 대안을 유지한다.
- 순수 검증 `PersonalFinanceMath.normalizeReferenceRate`가 base/quote·양수·숫자 형식·유효한 날짜·범위를 확인한다. 한국시간 오늘과 기준일을 비교하여 미래/7일 초과 자료를 거부하고 3일 초과는 화면에 안내한다. 기준일은 일자이며 고시 시각으로 꾸미지 않는다. 실제 조회 시각은 별도로 한국시간으로 표시한다.
- API의 1 JPY/VND/IDR당 원화 값은 100을 곱해 100엔/동/루피아 기준 입력칸에 넣는다. 편집 가능한 입력 표시를 소수 여섯 자리까지 반올림하며 이후 계산은 사용자가 볼 수 있는 그 값을 사용한다. 내부 계산은 결과 표시 전 반올림하지 않는다.
- 입력란 이름은 중립적인 ‘계산 기준환율’이다. 자동 입력은 ‘Frankfurter 참고환율’·기준일·조회 시각을 결과 및 공통 내보내기에 보존하고 추정임을 알린다. 사용자가 수정하면 자동 출처 표시를 제거하고 ‘직접 입력’으로 바꾼다. 통화 변경·수동 편집 뒤 도착한 응답은 값을 덮어쓰지 않는다. 명시적으로 불러오기를 다시 누르면 참고환율을 재적용한다.
- 서버 API, 저장 환율 JSON, 정기 수집 도구, 전용 GitHub Actions 배포 워크플로와 그 테스트를 제거했다. 사이트는 기존 GitHub Pages 배포 방식을 그대로 사용할 수 있고 별도 설정·API 키가 필요 없다. `file://` 대신 일반 HTTP 로컬 서버로 확인한다.
- 실제 Chrome의 일반 정적 로컬 페이지에서 1 USD당 1,339.29원, 기준일 2026-11-11 참고환율이 직접 적용되는 것을 확인했다. 1,400원으로 수동 편집하면 자동 출처가 사라지고 직접 입력 안내가 표시됐다. 실제 운영 도메인에서의 배포 후 확인은 아직 수행하지 않았다.
- `tests/personal-finance-math.test.js`에 JPY 단위·통화쌍·잘못된 숫자/날짜·미래/오래된 자료 검증을 추가했다. DOM 테스트는 직접 API 호출 경로, 수동 우선, 응답 순서, 실패 후 값 유지, 재시도, 결과 출처·PNG/PDF/공유 연결을 확인한다. 내보내기는 스텁으로 연결을 검증한다.

## 은퇴자금

[국민연금공단 간단재무설계](https://csa.nps.or.kr/ohkd/simplfncldesign/UHKD0101M0.do)의 현재 가치 생활비·물가·세후수익률 구분을 참고한 독립적인 월별 현금흐름 모델이다. 공단의 산식을 복제하거나 공단 조회 결과와 같다고 주장하지 않는다.

- 월 수익률 = (1 + 연 수익률)^(1/12) − 1. 은퇴 전에는 월 수익을 반영한 뒤 고정 명목 저축액을 월말에 더한다.
- 생활비는 현재 가치 입력에서 은퇴 전·후의 물가를 월 복리로 반영한다. 월 연금은 첫 수령 시점의 명목 세후 금액에서 별도 증가율을 적용한다.
- 은퇴 후 순서: 월 수익 → 연금 → 생활비. 필요 시작자금은 마지막 달부터 `max(0, (다음 달 필요 잔액 + 생활비 − 연금) / (1 + 월 수익률))`로 역산한다. 미래 연금을 미리 빌려 쓰지 않는다.
- 나이는 정수다. 연금 시작은 은퇴 나이 이상으로 입력한다. 이미 수령 중인 연금은 은퇴 나이와 그 시점의 연금액으로 입력하도록 안내한다. 서로 다른 연금 시작·종료 시점은 하나로 단순화한다.
- 자산이 정확히 0원이 되는 때와 생활비를 처음 전액 충당하지 못하는 달을 구분한다. 부족 이후 늦게 시작한 연금으로 자산이 다시 증가할 수도 있다.
- 검증 예: 60세 즉시 은퇴, 90세 종료, 월 생활비 200만원, 65세부터 월 연금 100만원, 모든 증가율 0 → 필요자금 4억 2천만원. 3억원으로 시작하면 80세 도달 때 잔액 0원, 첫 부족은 80세 1개월이다.
- ±2%p 고정 수익률 민감도는 안전 인출률이나 성공 확률이 아니다. 수익률 순서 위험·세금 자동 산출·일시 지출·사망 확률은 제외한다. 연도별 표는 펼쳐서 확인할 수 있으며 공통 내보내기는 현재 표시 상태를 사용한다.

## 리밸런싱

[한국투자공사 전통자산 운용](https://kic.kr/ko/investment/portfolio/traditional-assets)의 자산배분·리밸런싱 개념을 참고했다. 아래 배분 알고리즘은 이 도구의 계산 규칙이며 공사의 운용 전략이 아니다.

- 같은 시점의 원화 평가액을 자산 2~20개로 입력한다. 목표 비중은 소수 둘째 자리까지, 합계 100%여야 한다.
- 전체 조정: (현재 총액 + 추가금) × 목표 비중 − 현재 평가액.
- 매도 없이 추가 투자: 조정 후 총액에 대한 목표 평가액과 현재 평가액의 양의 차액에 비례해 추가금을 배분한다. 목표 비중에 도달하지 못할 수 있다.
- 원 단위 최대 나머지 배분으로 총 평가액과 순매수액을 보존한다. 세금·수수료·최소 주문 단위·체결 가격은 제외한다.
- 매도 없는 이론상 최소 추가금 = `max(0, max(현재 평가액_i / 목표 비율_i − 현재 총액))`를 원 단위 올림. 보유액이 있는 자산의 목표가 0%이면 유한한 추가금으로 불가하다. 계산값이 1조원을 넘으면 범위 밖으로 표시한다. 이 값은 이번에 입력한 추가금과 별개다.
- 검증 예: 600만원/400만원, 목표 50%/50% → 전체 조정은 100만원 매도/매수. 100만원만 추가하면 54.55%/45.45%, 정확한 목표에 필요한 최소 추가금은 200만원이다.

각 페이지의 독창적인 512×512 PNG, OG/Twitter URL·크기·alt를 적용했다. 프롬프트·파일 목록은 `images/og/README.md`에 기록했다. 배포 PNG의 비렌더링 메타데이터를 제거하고 IHDR/sRGB/IDAT/IEND 및 CRC를 확인했다. 이미지 메타데이터 유무가 검색 순위에 불이익을 준다는 주장은 근거로 사용하지 않는다.
