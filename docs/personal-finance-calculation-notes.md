# 환전·은퇴자금·리밸런싱 계산 노트

최초 계산 검토일: 2026-11-11, 환전 조회·UI 보완일: 2026-11-12 (한국시간). 세 도구는 사용자 입력을 계산한다. 환전은 하나은행 최신 고시환율 자동 조회와 직접 입력을 지원한다. 초 단위 시장 시세, 금융상품 금리, 추천 자산 비중은 제공하지 않는다. 수수료·투자 조건의 기본값은 임의 예시다.

## 환전수수료

[KB증권 환전 설명서](https://fdata.kbsec.com/agree/notice55.pdf)의 매수 시 기준환율에 스프레드를 더하고 매도 시 빼는 구조를 참고했다. 문서의 특정 상품 수수료율을 현재 공시값으로 가져오지 않았다. [은행연합회 외환길잡이](https://exchange.kfb.or.kr/)는 사용자의 조건 확인용 링크다.

- 우대 후 스프레드율 = 기본 수수료율 × (1 − 우대율).
- 적용 환율 = 매매기준율 × (1 ± 우대 후 스프레드율). 매수는 +, 매도는 −.
- 외화 기준: 외화 금액 × 적용 환율 ÷ 고시 단위에 별도 비용을 매수 시 더하고 매도 시 뺀다.
- 원화 기준: 매수는 별도 비용 차감 후 받을 외화를, 매도는 비용을 차감하고 목표 원화를 받는 데 필요한 외화를 역산한다. 두 조건은 항상 같은 요청 금액으로 비교한다.
- JPY는 100엔 고시를 사용한다. 통화·직접 고시 단위 변경 시 기존 기준율을 지워 잘못된 단위 사용을 방지한다.
- 검증 예: 1,000 USD, 기준율 1,400원, 스프레드 1.75%, 우대 90%, 별도 비용 0 → 매수 1,402,450원. 우대 50% 조건보다 9,800원 적다. 100엔당 950원으로 10만엔의 수수료 전 환산액은 95만원이다.
- 송금 중계·수취 비용, 카드 국제브랜드 수수료, 현찰 권종 및 거래단위는 자동 반영하지 않는다.

### 최신 고시환율 조회 — 2026-11-12

[하나은행 현재환율](https://www.kebhana.com/cont/mall/mall15/mall1501/index.jsp)에서 사용하는 [공개 조회 화면](https://www.kebhana.com/cms/rate/wpfxd651_01i.do)과 해당 화면이 호출하는 `https://www.kebhana.com/cms/rate/wpfxd651_01i_01.do`를 읽기 전용으로 확인했다. 은행 화면의 현재 회차(`pbldDvCd=3`)와 한국시간 조회일을 사용한다. 별도 인증키 없이 실제 응답의 매매기준율·고시 시각·회차를 확인했다. 공개 화면을 읽는 방식이며 은행이 보장하는 제휴 API는 아니므로 화면 구조나 접근 정책이 바뀌면 조회가 실패할 수 있다.

- 서버: `api/exchange-rates.js`. 고정된 은행 주소만 요청하고 URL·날짜·사용자 금액을 외부 입력으로 받지 않는다. 금액·수수료·개인정보를 은행에 전송하지 않는다. 별도 외부 라이브러리나 인증키를 추가하지 않았다.
- 응답: 출처 URL, 원 고시 시각(한국시간), 회차, 실제 수집 시각과 USD·JPY·EUR·CNY의 매매기준율/고시 단위. 현찰 매수·매도나 송금 환율을 기준율로 잘못 읽지 않도록 표 머리글·열 수·통화·단위·양수 여부·중복·고시 시각을 검증한다. 구조가 달라지면 추정하지 않고 502로 처리한다.
- JPY는 100엔 단위를 유지한다. 은행 설명에 따라 CNY는 홍콩시장에서 거래되는 위안화 고시라는 점을 표시한다. 휴일·첫 고시 전에는 전 영업일 값일 수 있으므로 고시일을 오늘 날짜로 바꾸지 않는다. 14일을 넘긴 고시나 5분 넘게 미래인 고시는 거부한다.
- 요청 제한: 서버 8초, 브라우저 10초 타임아웃. 동시 서버 조회를 병합하고 최대 60초 캐시한다. CDN에는 수집 후 남은 TTL만 설정해 두 캐시가 누적되어 120초가 되지 않도록 한다. [Vercel 캐시 헤더 공식 문서](https://vercel.com/docs/caching/cache-control-headers)를 확인했다. 실패 응답은 캐시하지 않는다.
- 브라우저: `scripts/exchange-rate-loader.js`. 진입·지원 통화 변경 시 조회하고 버튼으로 재조회한다. 주기적인 폴링은 하지 않는다. 통화 변경·직접 입력 시 이전 요청을 취소하고, 응답이 늦게 도착해도 직접 입력값이나 다른 통화의 기준율을 덮어쓰지 않는다. 기타 통화는 수동 입력만 지원한다.
- 실패 시 입력값을 유지하고 직접 입력 방법을 안내한다. 최초 기준율을 비워 두어 조회 실패를 예시 환율로 오인하지 않도록 했다. 수동 편집 시 은행 출처 표시를 제거한다. 자동 조회한 값은 결과/공통 내보내기에도 출처·고시 시각·회차·단위가 남는다.
- 단순 정적 서버에서는 `/api/exchange-rates`가 실행되지 않는다. Vercel Functions 또는 같은 계약의 서버 엔드포인트가 필요하며, 지원하지 않는 호스팅에서는 수동 계산이 작동한다. 배포와 운영 지역의 외부 연결 검증은 별도다.

A·B의 브라우저 기본 fieldset 테두리를 제거하고, 의미 있는 그룹 이름·제목과 남색/청록 배지를 갖춘 비교 카드로 바꿨다. 데스크톱은 두 열, 768px 이하에서는 한 열이며 기존 입력·초점·도움말 규칙을 재사용한다. 새 클래스에만 스타일을 적용해 다른 계산기 화면을 유지한다.

검증: 실제 은행 응답과 새 서버 함수의 HTTP 200, USD·JPY·EUR·CNY의 기준율/단위·고시 시각 대조를 완료했다. `tests/exchange-rates-api.test.js`는 고시 시각·열 변경·누락/오류·캐시·동시 요청을 검사하고 `npm test`에 포함했다. `tests/personal-finance-dom.test.js`는 자동 조회·직접 입력·통화 변경 경쟁·단위 오류·실패 후 유지·재시도·출처를 추가 검증한다. 73개 페이지의 공통 DOM 검사를 통과했다. 실제 Chrome에서 자동 입력, 결과 출처, 데스크톱 비교 카드와 390px 모바일 카드·계산을 확인했다. 실제 PNG/PDF 파일 렌더링과 운영 CDN 동작은 미검증이며 공통 내보내기 연결은 스텁으로 확인한다.

## 은퇴자금

[국민연금공단 간단재무설계](https://csa.nps.or.kr/ohkd/simplfncldesign/UHKD0101M0.do)의 현재 가치 생활비·물가·세후수익률 구분을 참고한 독립적인 월별 현금흐름 모델이다. 공단의 산식을 복제하거나 공단 조회 결과와 같다고 주장하지 않는다.

- 월 수익률 = (1 + 연 수익률)^(1/12) − 1. 은퇴 전에는 월 수익을 반영한 뒤 고정 명목 저축액을 월말에 더한다.
- 생활비는 현재 가치 입력에서 은퇴 전·후의 물가를 월 복리로 반영한다. 월 연금은 첫 수령 시점의 명목 세후 금액에서 별도 증가율을 적용한다.
- 은퇴 후 순서: 월 수익 → 연금 → 생활비. 필요 시작자금은 마지막 달부터 `max(0, (다음 달 필요 잔액 + 생활비 − 연금) / (1 + 월 수익률))`로 역산한다. 미래 연금을 미리 빌려 쓰지 않는다.
- 나이는 정수다. 연금 시작은 은퇴 나이 이상으로 입력한다. 이미 수령 중인 연금은 은퇴 나이와 그 시점의 연금액으로 입력하도록 안내한다. 서로 다른 연금 시작·종료 시점은 하나로 단순화한다.
- 자산이 정확히 0원이 되는 때와 생활비를 처음 전액 충당하지 못하는 달을 구분한다. 부족 이후 늦게 시작한 연금으로 자산이 다시 증가할 수도 있다.
- 검증 예: 60세 즉시 은퇴, 90세 종료, 월 생활비 200만원, 65세부터 월 연금 100만원, 모든 증가율 0 → 필요자금 4억 2천만원. 3억원으로 시작하면 80세 도달 때 잔액 0원, 첫 부족은 80세 1개월이다.
- ±2%p 고정 수익률 민감도는 안전 인출률이나 성공 확률이 아니다. 수익률 순서 위험·세금 자동 산출·일시 지출·사망 확률은 제외한다. 연도별 표는 펼쳐서 확인할 수 있으며 공통 내보내기는 현재 표시 상태를 사용한다.

## 리밸런싱

[한국투자공사 전통자산 운용](https://kic.kr/ko/investment/portfolio/traditional-assets)의 자산배분·리밸런싱 개념을 참고했다. 아래 배분 알고리즘은 이 도구의 계산 규칙이며 공사의 운용 전략이 아니다.

- 같은 시점의 원화 평가액을 자산 2~20개로 입력한다. 목표 비중은 소수 둘째 자리까지, 합계 100%여야 한다.
- 전체 조정: (현재 총액 + 추가금) × 목표 비중 − 현재 평가액.
- 매도 없이 추가 투자: 조정 후 총액에 대한 목표 평가액과 현재 평가액의 양의 차액에 비례해 추가금을 배분한다. 목표 비중에 도달하지 못할 수 있다.
- 원 단위 최대 나머지 배분으로 총 평가액과 순매수액을 보존한다. 세금·수수료·최소 주문 단위·체결 가격은 제외한다.
- 매도 없는 이론상 최소 추가금 = `max(0, max(현재 평가액_i / 목표 비율_i − 현재 총액))`를 원 단위 올림. 보유액이 있는 자산의 목표가 0%이면 유한한 추가금으로 불가하다. 계산값이 1조원을 넘으면 범위 밖으로 표시한다. 이 값은 이번에 입력한 추가금과 별개다.
- 검증 예: 600만원/400만원, 목표 50%/50% → 전체 조정은 100만원 매도/매수. 100만원만 추가하면 54.55%/45.45%, 정확한 목표에 필요한 최소 추가금은 200만원이다.

각 페이지의 독창적인 512×512 PNG, OG/Twitter URL·크기·alt를 적용했다. 프롬프트·파일 목록은 `images/og/README.md`에 기록했다. 배포 PNG의 비렌더링 메타데이터를 제거하고 IHDR/sRGB/IDAT/IEND 및 CRC를 확인했다. 이미지 메타데이터 유무가 검색 순위에 불이익을 준다는 주장은 근거로 사용하지 않는다.
